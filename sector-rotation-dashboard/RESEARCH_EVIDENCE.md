# Weekly research evidence contract
The only weekly research edit is `site/data/research-evidence.json` (public; no personal data). Keep schema_version 1, reviewed_at ISO date of actual review, and events array. Preserve existing event IDs and dated records; update state to resolved/superseded instead of deleting. Add an updated event with its own ID when facts change. A structural active record remains visible; routine active evidence rolls into supporting details after 28 days relative to reviewed_at. Two recent active items max per card, older evidence expandable. Medium materiality stays within cards; high materiality can enter Overview priorities (once per event). Source URLs HTTPS, issuer/regulator primary wherever possible; date is event date, not publication date if different; fact and implication distinct. kind confirmed/guidance/reported; materiality high/medium; state active/resolved/superseded; structural true/false; impacts entries symbol,tab,key,title,tone,implication, optional overview:true and optional assessment:{status,reason}. tone positive/negative/mixed/neutral. Only confirmed high-materiality active events with explicit reason may override assessment; no overriding reported figures. Driver statuses positive/mixed/negative/unknown; risk high/watch/disclosed/clear/structural; thesis support/watch/pressure/neutral/unknown. Newest explicit qualifying change wins; resolve or supersede when no longer justified. Do not promote a single event into a sustained trend. Use the exact card keys from stocks.js: driverGroups names; financial insight IDs earnings,leverage,growth,shares,cash,capex,runway; risk exposureDimensions or filing IDs (new descriptive risk key permitted for material unquantified exposures); peer key consolidated (AMZN aws/retail/ads/consolidated); thesisConfig checks exact first string. Avoid duplicate interpretations, no standalone news section. If source unavailable, do not invent or update. No private holdings or notes. Update reviewed_at after genuine review, even no material changes. Keep the existing company snapshots separate; weekly changes only to this JSON unless user asks otherwise. Validate JSON, tests, commit using latest main SHA with compare-and-swap, verify workflow deployment or explicitly report pending/failure.
